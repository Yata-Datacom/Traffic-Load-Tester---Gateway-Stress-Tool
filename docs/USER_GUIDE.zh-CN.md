# Traffic Studio 2.0 使用指南

> 适用于 **v2.0.0**。示例目标使用文档地址 `192.0.2.10`、`198.51.100.20`，不要替换成未授权设备。

## 1. 安全边界

Traffic Studio 是**压力测试工具**，不是通用扫描器。

- 只对你拥有或已获得书面授权的目标测试
- 高并发/不限速前先确认业务窗口、链路带宽和维护窗口
- 不要对公网、运营商、客户生产网做无授权压测
- 默认目标是文档地址，不会命中真实设备
- 启动前必须勾选「我确认已获得对该目标的测试授权」

## 2. 启动

```bash
python traffic_studio.py
```

或双击 `traffic_studio.pyw`（无控制台）。也可以从 Releases 下载单文件 exe。

V1 旧界面仍可用：

```bash
python traffic_test_gui.py
```

## 3. 总览

- 最近一次 PPS / Mbps
- 历史记录数、可用场景数
- 最近结果表
- 安全流程提示

按钮可直接进入流量测试、目标诊断、结果历史。

## 4. 流量测试

### 4.1 目标与端口

- **目标 IP / 主机**：IP 或可解析主机名
- **端口表达式**：
  - `8080`：单端口
  - `80,443`：多端口去重排序
  - `100-1000`：连续范围
  - `100-1000:50`：从范围中随机取 50 个不重复端口
- **默认网关**：点「探测网关」读取本机默认路由，选择后自动填入目标

### 4.2 协议

| 协议 | 是否需要目标监听 | 说明 |
|---|---|---|
| UDP | 否 | 直接发数据报 |
| TCP | 是 | 建立完整 TCP 连接后发送 |
| TCP SYN | 否 | 非阻塞半开连接，压新建会话能力 |

TCP 测试可以配合右侧「本机 TCP 接收端」做环回验证：先启动接收端，再对 `127.0.0.1` 和相同端口发起测试。

### 4.3 负载参数

- **并发线程**：1–500
- **包大小**：1–65535 B；预设 64/256/512/1024/1460
- **速率**：每线程每秒包数，0–50000；0 = 不限速
- **持续时间**：0 = 手动停止；大于 0 时到点自动停止

`rate=0` 和环回地址全速测试都会二次确认。

### 4.4 观察指标

- 实时 PPS、Mbps
- 总包数、运行时长
- 进度条（设置了持续时间时）
- 日志：启动参数、停止汇总、TCP 连接错误、接收端状态

## 5. 目标诊断

诊断不发送压测流量，适合上线前检查。

### 5.1 Ping

- 4 个 ICMP 包
- 输出：丢包率、RTT 最小/平均/最大、抖动
- 兼容中文/英文 Windows `ping` 输出

### 5.2 DNS

解析目标主机名，列出 A/AAAA 地址。解析失败会在结果列标红。

### 5.3 TCP 端口

按端口表达式逐个 `connect`，最多检查 50 个端口，显示每个端口的连接耗时或错误。

### 5.4 默认网关

读取本机默认路由，显示下一跳和网卡别名；可据此选择压测目标。

## 6. 测试场景

内置四个场景：

| 场景 | 协议 | 端口 | 包大小 | 速率 | 并发 |
|---|---|---|---|---|---|
| 网关 Web 压测 | TCP | 80,443 | 512 | 1000 | 20 |
| DNS 53 压测 | UDP | 53 | 256 | 2000 | 10 |
| 视频 UDP 大包 | UDP | 5000 | 1200 | 2000 | 30 |
| TCP SYN 握手 | TCP SYN | 80,443 | 64 | 2000 | 50 |

- 选择场景后点「加载场景」
- 调整参数后点「保存当前」保存自定义场景
- 自定义场景保存在本机 `scenarios.json`，不会提交到仓库
- 内置场景不可删除

## 7. 结果历史

每次测试停止或自动结束后自动写入 `runs.json`：

- 时间、目标、端口、协议
- 并发、包大小、速率、时长
- 总包数、总字节、平均 PPS、平均 Mbps

历史页支持：

- 刷新
- 导出 CSV 到 `reports/`
- 打开报告目录
- 清空本机历史

## 8. 数据与隐私

以下文件只在本机，已加入 `.gitignore`：

- `runs.json`
- `scenarios.json`
- `reports/`
- `build/`、`dist/`、`*.exe`

不要提交真实目标、测试结果、抓包或客户拓扑。

## 9. 常见问题

**TCP 一直 connect refused？**  
目标没有监听该端口。先用「目标诊断 → TCP 端口」确认，或启动右侧内置接收端做本机验证。

**Ping 不通但 TCP 端口通？**  
目标/中间设备可能禁 ICMP；以 TCP 诊断结果为准。

**PPS 上不去？**  
检查并发、速率、网卡/CPU、目标处理能力；`rate=0` 时受本机性能限制。

**历史没有记录？**  
只有实际发出包并正常停止的测试才会记录；启动失败或 0 包不会写入。

**换机器后历史/场景不见了？**  
它们保存在程序目录，不随 exe 分发；复制 `runs.json` / `scenarios.json` 即可迁移。
